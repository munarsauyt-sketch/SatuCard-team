# Работа команды SatuCard

## Исходная версия

Файлы в этом архиве — общий учебный прототип, ранее созданный с помощью Codex. Первый коммит нового репозитория должен называться `Import AI-assisted SatuCard starter`. Он фиксирует исходную версию и не засчитывается как личная новая функция участника. Старую историю Git в архив не включали. Не приписывайте старые изменения другим людям.

## Роли и новые функции

| Участник | Ветка | Личная функция | Три этапа работы |
| --- | --- | --- | --- |
| Владелец репозитория | `feature/interactive-comparison` | Интерактивное сравнение исходного фото и готовой карточки на главной | Разметка; мышь и касание; клавиатура, доступность и мобильная проверка |
| `nurlybekchel` | `feature/dark-theme` | Переключение светлой и тёмной темы на всех трёх страницах | Общие цветовые переменные; тёмное оформление и кнопка; сохранение выбора и проверка |
| `Sanzhar425` | `feature/photo-zoom` | Масштаб фото в редакторе вместе с уже существующим перемещением | Элементы управления; применение в Canvas; сброс, PNG и проверка |

Коммиты делают только после реальной работы. Название каждого коммита должно описывать конкретное изменение. Не создавайте пустые или фиктивные коммиты ради количества.

## Создание нового репозитория

1. Владелец создаёт на GitHub новый пустой репозиторий `SatuCard-team` под своим существующим аккаунтом. Не добавляет при создании README, `.gitignore` или лицензию: они уже лежат в архиве.
2. Распаковывает архив в новую папку. Не копирует в неё `.git` из старого проекта.
3. В терминале, открытом именно в новой папке, выполняет команды ниже. Имя и адрес заменяет на свои. Адрес должен быть связан с его аккаунтом GitHub; можно использовать адрес `noreply` из настроек GitHub.

```powershell
git init -b main
git config --local user.name "ВАШЕ ИМЯ"
git config --local user.email "ВАШ АДРЕС GITHUB"
git add .
git commit -m "Import AI-assisted SatuCard starter"
git remote add origin https://github.com/munarsauyt-sketch/SatuCard-team.git
git push -u origin main
```

Если репозиторий создан под другим аккаунтом или с другим названием, замените URL. После публикации владелец приглашает `nurlybekchel` и `Sanzhar425`: **Settings → Collaborators → Add people**. Каждый принимает приглашение на своём аккаунте.

## Работа каждого участника

Каждый участник клонирует репозиторий на своём компьютере. Не работайте втроём в одной папке OneDrive. Перед первым коммитом настройте личные данные Git в своей копии:

```powershell
git clone https://github.com/munarsauyt-sketch/SatuCard-team.git
cd SatuCard-team
git config --local user.name "СВОЁ ИМЯ"
git config --local user.email "СВОЙ АДРЕС GITHUB"
git status
```

Владелец создаёт `feature/interactive-comparison`, `nurlybekchel` — `feature/dark-theme`, `Sanzhar425` — `feature/photo-zoom`:

```powershell
git switch -c feature/НАЗВАНИЕ-СВОЕЙ-ФУНКЦИИ
```

После каждого завершённого этапа: проверьте результат, добавьте изменённые файлы, создайте коммит и посмотрите его автора.

```powershell
git status
git add ИМЕНА_ИЗМЕНЁННЫХ_ФАЙЛОВ
git commit -m "Короткое описание реального изменения"
git log -1 --format="%h %an <%ae> %s"
```

После трёх этапов отправьте свою ветку:

```powershell
git push -u origin feature/НАЗВАНИЕ-СВОЕЙ-ФУНКЦИИ
```

На GitHub откройте Pull Request из своей ветки в `main`. Владелец просматривает изменения и объединяет через **Create a merge commit**. Не выбирайте **Squash and merge**, иначе три коммита станут одним в основной ветке. Если `main` изменился за время работы, обновите свою ветку и разрешите конфликты перед объединением.

## Что проверить перед защитой

- На GitHub открыть вкладку **Commits** и три Pull Request. У каждого участника должны быть три отдельных содержательных коммита, связанных с его аккаунтом.
- Открыть `index.html` двойным щелчком в обычном Chrome или Edge. Проверить переходы между страницами.
- В редакторе загрузить своё JPG, изменить название и цену, выбрать стиль и формат, настроить масштаб и положение фото, скачать PNG и открыть сохранённый файл.
- Проверить сравнение мышью, пальцем и клавиатурой, а тему — на всех страницах и после обновления браузера.
- Проверить ширину телефона, включая 320 px.
