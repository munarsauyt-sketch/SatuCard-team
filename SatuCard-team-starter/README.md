# SatuCard: запуск и архитектура

Редактор находится в `editor.html`. Для локальной проверки интерфейса можно открыть `index.html` в браузере. Скачивание PNG работает без сервера. Публикация и открытие карточки по ссылке требуют развёрнутых серверных функций и базы данных.

**Работающий сайт:** [satucard-team.vercel.app](https://satucard-team.vercel.app/). Публичный тестовый пример: [карточка наушников](https://satucard-team.vercel.app/card.html?id=eabc5695-b4da-48bc-ace0-c5a76bc1e184).

## Структура

- `index.html`, `editor.html`, `examples.html` — страницы сайта.
- `card.html`, `card.js` — опубликованная карточка по идентификатору.
- `editor.js`, `brand-kit.js`, `theme.js` — редактор, фирменный стиль и тема.
- `styles.css`, `theme.css`, `assets/` — оформление и локальные ресурсы.
- `api/cards.js` — проверяет запрос, загружает готовый JPEG и записывает метаданные.
- `api/card.js` — читает карточку из базы по UUID.
- `database/schema.sql` — таблица PostgreSQL и контейнер Supabase Storage.
- `tests/api.test.js` — проверки серверной логики.

## Настройка Supabase

1. Создайте проект Supabase. В SQL Editor выполните [`database/schema.sql`](database/schema.sql).
2. В настройках проекта скопируйте Project URL и секретный ключ `sb_secret_...` (или действующий service role key, если проект использует старый формат).
3. Не записывайте ключ в файлы сайта и не публикуйте его в репозитории.

## Публикация на Vercel

1. Импортируйте репозиторий `munarsauyt-sketch/SatuCard-team` в Vercel.
2. Укажите **Root Directory:** `SatuCard-team-starter`. Оставьте Framework Preset `Other`; команда сборки не нужна.
3. В Environment Variables задайте `SUPABASE_URL` и `SUPABASE_SECRET_KEY` для Production и Preview. Образец имён есть в `.env.example`.
4. Выполните Deploy. Проверьте `index.html`, `editor.html`, `examples.html` и публикацию карточки.

Функции вызываются на том же домене, что и сайт, поэтому секретный ключ остаётся на сервере. Исходный загруженный файл обрабатывается в браузере. Только готовый JPEG до 2 МБ отправляется при публикации. Публичную ссылку может открыть любой, у кого она есть.

## Локальные проверки

В папке приложения выполните `npm test`. Для полноценной проверки публикации локально нужны переменные окружения из `.env.example` и `vercel dev`. При открытии через `file://` кнопка «Опубликовать» объясняет, что нужен опубликованный сайт.

После развёртывания проверены главная, редактор, скачивание PNG, публикация примерной карточки и открытие её изображения по публичной ссылке.

## Ограничения прототипа

ИИ и удаление фона пока не реализованы; они запланированы на 8–15 недели. Нет аккаунтов, панели управления, удаления опубликованных карточек, защиты от массовых публикаций и автоматической отправки на маркетплейсы. Перед публичным запуском для большого числа пользователей понадобятся ограничения запросов, политика хранения и удаление карточек.
