# SatuCard: запуск и архитектура

Редактор находится в `editor.html`. Для локальной проверки интерфейса можно открыть `index.html` в браузере. Скачивание PNG работает без сервера. Регистрация, вход, публикация и личный кабинет требуют опубликованного сайта и Supabase.

**Работающий сайт:** [satucard-team.vercel.app](https://satucard-team.vercel.app/). Публичный тестовый пример: [карточка наушников](https://satucard-team.vercel.app/card.html?id=eabc5695-b4da-48bc-ace0-c5a76bc1e184).

## Структура

- `index.html`, `editor.html`, `examples.html` — страницы сайта.
- `auth.html`, `auth.js`, `auth-client.js` — регистрация, вход, обновление и сохранение сессии Supabase Auth.
- `dashboard.html`, `dashboard.js` — профиль и список опубликованных карточек.
- `card.html`, `card.js` — опубликованная карточка по идентификатору.
- `editor.js`, `brand-kit.js`, `theme.js` — редактор, фирменный стиль и тема.
- `styles.css`, `theme.css`, `app.css`, `site.js`, `assets/` — оформление, меню, анимации и локальные ресурсы.
- `api/cards.js` — проверяет запрос, загружает готовый JPEG и записывает метаданные.
- `api/card.js` — читает карточку из базы по UUID.
- `api/my-cards.js` — проверяет токен и отдаёт карточки текущего пользователя.
- `database/schema.sql` — таблицы PostgreSQL, RLS, триггер профиля и контейнер Supabase Storage.
- `tests/api.test.js` — проверки серверной логики.

## Настройка Supabase

1. Создайте проект Supabase. В SQL Editor выполните [`database/schema.sql`](database/schema.sql). Схема повторно применима и к существующему проекту с карточками.
2. В настройках проекта скопируйте Project URL и секретный ключ `sb_secret_...` (или действующий service role key, если проект использует старый формат).
3. Не записывайте ключ в файлы сайта и не публикуйте его в репозитории.
4. В Authentication включите email signup. Для учебной версии подтверждение email отключено: встроенный почтовый сервис Supabase не отправляет письма внешним адресатам. Для коммерческого запуска настройте SMTP и включите подтверждение email. В URL Configuration укажите опубликованную страницу `auth.html` как Site URL.

Supabase Auth хранит пароли и сессии. При регистрации триггер создаёт запись в `public.profiles` с `id`, `name`, `email`, `created_at`. Политика RLS разрешает пользователю читать только собственный профиль. `public.cards.user_id` связывает новые карточки с автором; личный список проверяет токен на сервере. Старые демонстрационные карточки без `user_id` остаются доступными по публичным ссылкам.

## Публикация на Vercel

1. Импортируйте репозиторий `munarsauyt-sketch/SatuCard-team` в Vercel.
2. Укажите **Root Directory:** `SatuCard-team-starter`. Оставьте Framework Preset `Other`; команда сборки не нужна.
3. В Environment Variables задайте `SUPABASE_URL` и `SUPABASE_SECRET_KEY` для Production и Preview. Образец имён есть в `.env.example`.
4. Выполните Deploy. Проверьте регистрацию, вход, личный кабинет, скачивание PNG и публикацию карточки.

Frontend — статические HTML/CSS/JavaScript без сборки. Backend — Vercel Functions с REST API `POST /api/cards`, `GET /api/card?id=...` и `GET /api/my-cards`. Authentication — Supabase Auth; база — PostgreSQL; изображения — Supabase Storage. Ключ `sb_publishable_...` в `auth-client.js` публичен и работает с RLS. `SUPABASE_SECRET_KEY` используется только сервером. Исходный загруженный файл обрабатывается в браузере. Только готовый JPEG до 2 МБ отправляется при публикации. Публичную ссылку может открыть любой, у кого она есть.

## Локальные проверки

В папке приложения выполните `npm test`. Для полноценной проверки публикации локально нужны переменные окружения из `.env.example` и `vercel dev`. При открытии через `file://` кнопка «Опубликовать» объясняет, что нужен опубликованный сайт.

После развёртывания проверяйте сценарий: регистрация → вход → публикация → карточка в профиле → выход → повторный вход. При `file://` доступны интерфейс и PNG; авторизация и серверные действия требуют публичного HTTPS-сайта.

## Ограничения прототипа

ИИ и удаление фона пока не реализованы; они запланированы на 8–15 недели. Нет удаления опубликованных карточек и автоматической отправки на маркетплейсы. Для массового запуска понадобятся ограничения публикаций, политика хранения и функция удаления данных.
