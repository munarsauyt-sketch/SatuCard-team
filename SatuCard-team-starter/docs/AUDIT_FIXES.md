# Исправления аудита SatuCard

Ветка подготовки исправлений: `codex/audit-fixes-free-templates`. Изменения существующего редизайна сохранены. Graphify использован для навигации; граф не перестраивался. Перенос кода в `main` не применяет SQL-миграции к рабочей Supabase: порядок их применения приведён ниже. Если `main` подключена к автоматическому деплою, добавьте таблицы и RPC до выпуска новой версии API.

## Применение серверных изменений

Миграции подготовлены и проверены локально, **в рабочей базе не применялись**. Новую версию API нужно выпускать после добавления таблиц/RPC:

1. Сохранить резервную копию базы и проверить исторические заявки `plan_id = 'niche10'`. История подтверждённых платежей сохраняется; автоматические возвраты денег не выполняются.
2. Применить `database/publication-uploads.sql`. Без таблицы новая публикация завершится сообщением о временной недоступности до загрузки изображения.
3. После существующей `database/site-telemetry.sql` применить `database/telemetry-rate-limit.sql`. Пока RPC отсутствует, новая телеметрия ничего не записывает; сам сайт продолжает работать.
4. После существующих `database/paid-access.sql` и `database/pricing-v2-upgrade.sql` применить `database/free-templates-upgrade.sql`. Эта миграция обновляет обе функции заказа/подтверждения и исправляет старое расписание. Исходные SQL для чистой установки также обновлены.
5. Проверить Preview на отдельном тестовом аккаунте: вход, сохранение, публикация/обновление/удаление, публичная ссылка, отказ от снятого с продажи набора, покупка актуального тарифа. Реальные оплаты и вызовы платных моделей в локальных тестах не выполнялись.

Миграции повторяемые. Изменения расписания записываются в приватную `billing_schedule_repairs` со старыми и новыми датами. Перед восстановлением старых дат необходимо сверить уже использованный доступ и более поздние покупки; автоматического обратного сдвига нет. При откате приложения добавленные таблицы удалять не требуется.

### Сверка незавершённых публикаций

Инструмент использует `SUPABASE_URL` и `SUPABASE_SECRET_KEY` из окружения:

```text
node scripts/reconcile-publication-uploads.mjs
```

По умолчанию выполняются только чтение и вывод плана. Проверяются до 100 записей старше 24 часов. Если в любой карточке ещё используется изображение, оно сохраняется. При ошибке проверки ссылок удаление не производится.

```text
node scripts/reconcile-publication-uploads.mjs --apply
```

Только явный `--apply` выполняет план: удаляет подтверждённо неиспользуемые файлы и соответствующие записи журнала либо очищает журнал для используемых картинок. Инструмент не запускался против рабочей базы. Для постоянного обслуживания нужно подключить его к расписанию в доверенной серверной среде; расписание и секреты не добавлялись автоматически. Ранее существовавшие файлы, не попавшие в журнал, этот инструмент не перечисляет и не удаляет.

```text

npm run build
npm run test:interface-contract
npm run test:browser
npm run test:audit-browser
npm run test:redesign
npm run test:hero
```
