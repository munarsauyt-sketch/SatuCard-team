# Вход и регистрация через Google

Одна кнопка «Продолжить с Google» выполняет и вход, и первую регистрацию. Сайт использует существующий Supabase Auth и те же профили, идентификаторы пользователей, RLS и карточки. Переносить базу или создавать отдельную таблицу Google-пользователей не нужно.

## Настройка владельцем проекта

### 1. Google Cloud

Откройте Google Auth Platform в Google Cloud. Выберите проект SatuCard либо создайте отдельный проект.

1. В первоначальной настройке укажите название приложения `SatuCard`, свой контактный email и аудиторию **External**.
2. В **Clients → Create client** выберите **Web application**.
3. Название клиента: `SatuCard Web`.
4. **Authorized JavaScript origins:** `https://satucard-team.vercel.app`.
5. **Authorized redirect URIs:** `https://pnnaqvfcswdroldovbty.supabase.co/auth/v1/callback`.
6. Создайте клиента. Сохраните Client ID и Client Secret в менеджере паролей. Не добавляйте секрет в репозиторий, файл проекта или переписку.

Для обычного входа нужны только базовые данные аккаунта: `openid`, `email`, `profile`. Не запрашивайте доступ к Gmail, Drive или другим данным Google.

Если приложение находится в режиме **Testing**, добавьте свои аккаунты в **Audience → Test users**. Для доступа других продавцов переведите приложение в **Production**. Требования к оформлению приложения и проверке бренда определяет Google. Не выдавайте учебную версию за прошедший проверку Google коммерческий сервис.

### 2. Supabase

Откройте [Google provider](https://supabase.com/dashboard/project/pnnaqvfcswdroldovbty/auth/providers).

1. В форме **Google** вставьте Client ID и Client Secret из Google Cloud.
2. Включите **Enable Sign in with Google** и сохраните.
3. **Skip nonce checks** и **Allow users without an email** оставьте выключенными.
4. В **Authentication → URL Configuration** добавьте точный адрес `https://satucard-team.vercel.app/auth.html` в Redirect URLs. Не добавляйте произвольные внешние адреса и широкие шаблоны.
5. Для локальной проверки можно отдельно разрешить точный URL разработки, например `http://127.0.0.1:4174/auth.html`. Он не нужен для работы опубликованного сайта.

Google Client Secret хранится только у Supabase. Существующие `SUPABASE_URL` и `SUPABASE_SECRET_KEY` на Vercel менять не требуется.

## Как проходит вход

`auth-client.js` проверяет доступность провайдера, создаёт случайный PKCE verifier через Web Crypto, хранит его в `sessionStorage` текущей вкладки и отправляет только S256 challenge в Supabase. Supabase выполняет OAuth с Google и проверяет OAuth state.

После возврата в `auth.html?code=…` сайт сначала очищает адрес, затем обменивает одноразовый код вместе с verifier на Supabase-сессию. Код без соответствующей попытки входа из этой вкладки не принимается. Собственные токены доступа к сервисам Google приложение не сохраняет. Возврат всегда идёт в личный кабинет, внешние адреса `next` не используются.

Для аккаунтов с одним подтверждённым email Supabase поддерживает автоматическое связывание идентичностей. Это нужно проверить на существующем тестовом аккаунте: пользователь должен сохранить свой `id` и опубликованные карточки. Не создавайте собственное связывание по непроверенному email и не переписывайте `cards.user_id` вручную.

## Проверка перед включением для всех

- Новый пользователь: Google, личный кабинет, профиль, публикация и повторный вход.
- Существующий пользователь: вход Google с тем же email, прежний `id` и прежние карточки.
- Отмена в Google возвращает понятное сообщение и доступ к входу по email.
- Обновление кабинета сохраняет сессию, выход удаляет её.
- Ошибочная либо истёкшая ссылка входа не создаёт сессию.
- На телефоне и в обеих темах кнопка и ошибки читаемы.

Автоматические проверки: `node --test tests/*.test.js`.

Google-вход проверяет Google-идентичность, но не меняет режим регистрации по email. В текущей учебной конфигурации подтверждение email всё ещё выключено. Для коммерческого запуска нужны SMTP и подтверждение email. Токены сессии, как и раньше, находятся в хранилище браузера; XSS остаётся существенным риском, поэтому не подключайте непроверенные скрипты и не выводите пользовательский HTML.
